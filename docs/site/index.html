lmm, the Linux Mod Manager

Mod your games on Linux from a profile you can share and re-apply

lmm is a native Linux mod manager. It downloads mods from NexusMods, CurseForge, Thunderstore and the Steam Workshop, puts them in the game folder, and records every file it adds. Because it knows exactly what it added, it can update a mod, roll it back or take it out again without touching the game's own files.

Use it from the terminal, or from the web UI it opens in your browser. Both run the same engine.

Free and open source under the MIT license. One binary for x86-64 and ARM64 Linux.

For Linux players who mod their games

If you mod games on Linux today, you probably run a Windows mod manager under Wine, or unzip archives into the game folder and try to remember what went where. Then updating a mod, removing one, or setting up the same mods on a second computer is work you do by hand.

lmm runs natively on Linux. It finds your Steam games, and Battle.net games installed under Wine or Proton. For the games it already knows, such as Skyrim, Baldur's Gate 3 and Valheim, it fills in where the mods go. If you've modded a game before, lmm can scan its mod folder and take over the mods already there.

Your mod setup is a file, and lmm makes the game match it

A profile lists the mods a game should be running: which ones, which versions and in what order they load. lmm profile apply changes the game to match it. It installs what's missing, takes out what the profile no longer lists, and moves each mod to the version the profile names, even when that is an older one.

Lock a mod to one version and the lock holds through apply, deploy, update and rollback. Export a profile to a small YAML file to keep as a backup or send to a friend. Importing it on another computer downloads and installs the same mods at the same versions.

A game can have several profiles, such as a co-op setup that matches your friends' mods next to your solo game. Switching between them leaves the mods both use in place, and nothing lmm already has is downloaded again.

$ lmm profile export coop > coop.yaml
$ lmm profile import coop.yaml
$ lmm profile apply --dry-run
Apply plan for profile "default" (dry run)

Will install 2 mod(s):
  ↓ mod-workshop:BetterLanterns v1.4.0
  ↓ mod-workshop:WildlifeAI v0.7.0

A terminal and a browser, one engine

Run lmm serve and your browser opens on lmm's web UI: your library, search, updates, health checks, file conflicts, profiles and snapshots.

Everything the web UI does is also an lmm command, because both run the same code in the same binary, on the same database and profiles. Use the browser day to day. Use the terminal for scripts, or over SSH on another machine.

By default the web UI listens on 127.0.0.1, so nothing else on your network can reach it. It can also run in the background as a systemd user service.

Mods from the sites you already use, and from your own

  • NexusMods and CurseForge

    Sign in with an API key from your account page. lmm stores it encrypted on your computer and only ever sends it to that site.

  • Thunderstore

    Needs no key. For Unity games that load mods through BepInEx, such as Valheim and Lethal Company, lmm puts each plugin where the loader looks for it, whichever site it came from.

  • Steam Workshop

    Track the items Steam already installed, import a Workshop collection as a profile, or let lmm download an item and manage its own copy.

  • Your own sources

    Describe a local folder, a JSON or YAML mod list, or a REST API in a short YAML file. lmm installs and updates from it like a built-in source.

  • Files you downloaded

    Hand lmm an archive you downloaded yourself, for example from a free NexusMods account, and it manages that mod like any other.

  • Icarus

    Icarus has its own built-in source. lmm converts its .pak mods and merges them in load order.

See every change first, and undo it later

A preview before anything changes
The web UI shows the plan and waits for you to confirm it. In the terminal, commands that change things take --dry-run.
Back to an unmodded game
lmm purge puts the game folder back the way it was before lmm touched it. When a mod replaced one of the game's own files, lmm kept the original and puts it back.
Snapshots and rollback
Save a snapshot to bring the game back to later. lmm update rollback steps a mod back to its previous version.
Verify what's on disk
lmm verify checks downloaded files against their recorded checksums, and the game folder against what the profile provides. --fix only ever removes files lmm itself put there.
File conflicts
lmm conflicts lists every file two mods both provide, which mods they are, and which one wins.

Add --json for scripts

Add --json and a command prints exactly one JSON document on standard output. Warnings go inside the document, so piping it to jq is always safe. The web UI's /api/v1 returns the same documents.

$ lmm update --json | jq -r '.updates[] | "\(.installed_mod.name): \(.installed_mod.version) -> \(.new_version)"'
Better Lanterns: 1.3.2 -> 1.4.0
Map Markers: 0.9.1 -> 0.9.3
Night Sky Overhaul: 2.2.0 -> 2.3.0

lmm keeps itself up to date, and checks the signature first

Once a day lmm asks GitHub whether a new release is out. If you installed it from the release download or with go install, it installs the new version itself. First it checks the release's ed25519 signature against the keys built into lmm, then the download against its checksum. Anything that doesn't match is refused. Set auto_update: false, or use Setup → Updates in the web UI, to turn this off.

An lmm your package manager installed is never replaced by lmm. It tells you a new version is out and leaves the upgrade to your package manager.

What lmm doesn't do yet

lmm installs, deploys, updates, locks and reproduces Skyrim and Fallout mods. It can't yet walk you through a FOMOD installer's options, sort plugins automatically the way LOOT does, or import a Nexus Collection. All three are tracked as work (#354, #355, #597). If your setup depends on them, Limo or Mosaic serves it better for now. A profile does record load order, and you can change it in the terminal or the web UI.

The web UI is built for a desktop browser. On a phone, use the terminal over SSH.

Install lmm

Every release on GitHub Releases has packages and a plain download for x86-64 (amd64) and ARM64 (arm64).

Debian, Ubuntu, Fedora, openSUSE, Alpine

Download the .deb, .rpm or .apk from the latest release, then install it:

# Debian / Ubuntu
sudo dpkg -i lmm_<version>_linux_amd64.deb
# Fedora
sudo rpm -i lmm_<version>_linux_amd64.rpm
# openSUSE
sudo zypper install ./lmm_<version>_linux_amd64.rpm
# Alpine
sudo apk add --allow-untrusted ./lmm_<version>_linux_amd64.apk

Includes the man pages and shell completions.

Arch Linux

Each release carries a PKGBUILD for lmm-bin. It isn't on the AUR yet (#549).

mkdir lmm-bin && cd lmm-bin
curl -LO https://github.com/DonovanMods/linux-mod-manager/releases/latest/download/PKGBUILD
makepkg -si

Any Linux

Download lmm_<version>_linux_amd64.tar.gz (or arm64) and put lmm on your path. Installed this way, lmm updates itself.

tar -xzf lmm_*.tar.gz
mkdir -p ~/.local/bin && mv lmm ~/.local/bin/

With Go

Needs Go 1.27 or later.

go install github.com/DonovanMods/linux-mod-manager/v2/cmd/lmm@latest

Then run lmm serve and follow the setup in your browser, or lmm init for the same steps in the terminal. The guide walks you through it. If you change your mind, lmm purge puts the game folder back the way it was.
