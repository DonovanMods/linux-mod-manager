# v2 Phase 2 — "Lift Flows" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move every engine that still lives in `cmd/lmm` into `internal/core` behind Plan/Apply pairs, so that `lmm serve` can drive the same flows without reimplementing them — while the CLI stays byte-identical.

**Architecture:** Eight story branches off `v2` (F: pickups + hook lifecycle; G: file-selection policy; H: batch install; I: update/rollback plans; J: profile apply/sync/reorder; K: local scan + adopt; L: game detect + remaining `storage/config` reads; M: Plan/Apply for deploy/uninstall/purge + `--dry-run`), each a sequence of SDD tasks with a whole-branch review, merged `--no-ff` into `v2` in that order. Every lift follows the same recipe: **characterize** (capture tests / goldens for every output path the cmd engine has), **lift** (core Plan/Apply with typed Plan/Options/Result, events through the sink), **re-point** (cmd becomes flags → Plan → prompt → Apply → render), **ratchet** (consumed primitives unexported in the same task; the flow's chunk of `flows.go` moves to its own file; the boundary allow-list shrinks). The phase ends with a twin-sandbox live review like Phases 0 and 1.

**Tech Stack:** Go 1.27, cobra, testify, `encoding/json/v2` goldens, `log/slog`. No new dependencies.

**Spec:** `docs/plans/2026-08-27-v2-core-refactor-design.md` (tracked on `v2`) — §1 "Facade shape" / "What stays in cmd", §4 "Plan/Apply is the shape of every mutation" / "No callbacks into the frontend from Apply" / "Stale plans", §5 "Phase 2". Read it first; this plan argues from it. Deviations from the spec's literal text are listed under **Rulings** below and recorded in the spec's decisions log by Task 1.

## Global Constraints

- **Integration branch is `v2`.** Story branches fork from `v2` (`orca-ide worktree create --base-branch v2 --issue <n>`, fetch first); merge back locally with `git merge --no-ff`; push `v2` to `nerdwerx`. No PRs unless asked. Never touch `develop`/`main`.
- **No version bump** (`cmd/lmm/root.go` `version` stays `1.30.1`). CHANGELOG entries under `## [Unreleased]`, each carrying its issue number.
- **Byte-identical CLI output for every existing invocation, in every mode (`-v`, `--json`, plain).** The only permitted output additions are behind NEW flags introduced by this plan (`--dry-run` on `deploy`/`uninstall`/`purge`, Unit M) and `--help` text gaining those flags. Golden/capture tests under `cmd/lmm/` are frozen; a diff there is a defect, never a re-record — **except** the characterization goldens this plan itself adds *before* a lift, which are recorded once, on the pre-lift code, and then frozen.
- **Core never writes to stdout/stderr or reads stdin.** Diagnostics → `s.logger()`; user-facing facts → events or `Result` fields. A prompt is a `Plan` field the frontend inspects plus an `Options` field it sets.
- **Every lifted flow is a Plan/Apply pair**: `PlanX(ctx, …) (*XPlan, error)` is side-effect-free; `ApplyX(ctx, game, plan, opts, sink) (*XResult, error)` mutates under `beginOp`. Plans and Results carry snake_case `json` tags and a golden (the AST coverage test enforces the golden).
- **"Lifted" is verified by unexporting**: every `*core.Service` primitive whose last external caller a task removes is unexported (or deleted) in that same task. A task that leaves a now-unused export is incomplete.
- **`flows.go` shrinks every unit**: the lifted flow's methods and private helpers move to their own file (`install.go`, `update.go`, `rollback.go`, `uninstall.go`, `purge.go`, `deploy.go`, `switch.go`, `profile_apply.go`, `profile_sync.go`, `adopt.go`, `game_detect.go`, `selection.go`, `hooks.go`). Pure moves are their own commit (`git mv`-style, `-M` diff shows a rename) so reviewers can separate motion from change.
- **Boundary ratchet**: `cmd/lmm/boundary_test.go`'s allow-list entry for a package is removed in the task that removes the last import (Units K, L). Never add an entry.
- **`make man`** after any help-text change (Unit M adds flags) and commit `docs/man/man1/`.
- **`.envrc` exports real API keys.** Tests touching key resolution `t.Setenv`.
- **`gofmt -l ./cmd ./internal` must print nothing** before every commit; `make check` (fmt, lint, vet, `test -race`) is the gate for every task.
- **Tests use `context.Background()`** unless the test is about cancellation.

**Audit facts this plan relies on (verified 2026-08-28 on `v2` @ 59360ae):** `flows.go` is 5,601 lines holding 14 exported flows; `*core.Service` has 87 exported methods, 23 with zero `cmd` callers, `DownloadModToCache` dead everywhere, `IsSourceAuthenticated` test-only; `cmd/lmm` imports exactly `internal/{app,core,domain,source}` plus the three allow-listed `internal/source/custom` (source.go), `internal/source/steam` (game.go), `internal/storage/config` (10 files, 21 call sites). Engines in `cmd`: `batchInstallMods` (install.go:1165–1420, bypasses `ApplyInstall` entirely, hand-rolls hooks/lock/download/deploy/persist), `doProfileApply` (profile.go:878–1232, no core counterpart, no Plan/Result type), `doProfileSync` (profile.go:591–762), `doProfileReorder` (profile.go:770–870, **untested**), `runImportScan` (import.go:435–661) + `importExistingMod` (715–801) + `copyFileStreaming` (804–831, verbatim duplicate of core's unexported `importer.go:730`), `doImport` archive tail (import.go:130–431), `doGameDetect` (game.go:214–277, writes the default profile through `config.SaveProfile` directly, overwriting it), `applySingleUpdate` (update.go:588–756), `doUpdateRollback` pre-checks (update.go:887–901), `doUpdate` `lockedRefs` (update.go:389–396). The only cmd goldens are `mod_show_golden/` and `verify_golden/`; every other command's output is pinned by inline string assertions in `*_test.go`.

## Rulings (recorded in the decisions log by Task 1)

1. **`cmd/lmm/hooks.go` is deleted at the end of Unit K, not Unit F.** Unit F moves hook *resolution* into core and strips `Hooks/HookRunner/HookContext` from every `*Options` struct; the two remaining cmd-side hook sequencers (`batchInstallMods`, `doImport`'s archive tail) die with their engines in Units H and K. The spec's "#1 deletes hooks.go" is satisfied by the end of #6.
2. **`Installer.InstallBatch`/`UninstallBatch`, `BatchOptions`, `BatchResult`, `SkippedMod`, `InstalledModResult`, `UninstalledModResult` are deleted** (zero production callers; `applyInstallBatchMod` is the live batch engine). This retires #284 item 2 and #285 item 1 without tagging dead types.
3. **`ScanResult.Err`/`ErrorMessage` are removed** (never set; YAGNI). If `ScanLocal` needs per-entry errors, Unit K adds them with the error-as-text convention.
4. **`domain.DeployError` stays untagged** (an error type, not a wire type) — the existing exclusion comment is the record.
5. **`Plan` structs carry a `snapshot`** of the installed-mod set they were computed from (unexported field, `json:"-"`); every `Apply` re-derives it and returns `ErrStalePlan` on mismatch. One helper `installedSnapshot(ctx, gameID, profile)` + `checkPlanFresh(...)` used by every new Apply. Existing pairs (`Install`, `Import`, `Switch`) adopt it in the unit that touches them (H, K, J).
6. **Prompts stay callbacks in Phase 2.** `ConfirmConflicts`/`ConfirmInstall` are removed in Phase 3 per spec; new Plan/Apply pairs expose the decision as plan data + an `Options` bool from day one (`AcceptConflicts`, `Confirmed`) so nothing new needs Phase 3 surgery.
7. **`--dry-run` is added only where the spec says** (deploy, uninstall, purge; update already has it). `ConvergeDeployedFiles(dryRun)` is unexported in Unit M and its `dryRun` bool survives internally until `PlanDeploy` subsumes it; retiring the bool entirely is Phase 3.
8. **`DetectedGame` becomes `domain.DetectedGame`** and Steam scanning is exposed by `internal/app` (`app.DetectGames`), not `core` — core must not import concrete sources.
9. **The swallowed lock refusal in `doProfileApply`/`doProfileSync`** (an `UpsertMod` error is a `--verbose`-only warning) is preserved byte-for-byte in Phase 2 and filed as a Phase 3 behaviour fix (Task 0 files it).
10. **`#283` (per-source update-check counters) stays deferred to Phase 3** — a global counter changes `-v` output.
