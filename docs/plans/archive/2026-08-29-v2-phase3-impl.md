# v2 Phase 3 — "Contract Completion" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish the v2 contract: every command's `--json` emits core/domain types (cmd's view structs deleted), every mutating command has `--json` and runs without stdin, the last frontend callbacks leave core, `flows.go` and the boundary allow-list mechanism are gone, every exported core identifier is documented, the ruled behaviour deltas land, and the repo is ready for the v2.0.0 cut (whose timing and module-path mechanics are the owner's decision).

**Architecture:** Six story branches off `v2`, merged `--no-ff` in order: **N** contract prerequisites (core query/result types the CLI's JSON needs, structured results instead of pre-formatted strings, deterministic ordering, dead API deleted, the `core→custom` import replaced by an interface); **O** the `--json` switch on the nine commands that already have it (view structs deleted, cmd JSON goldens recorded once on the new shapes); **P** callbacks removed + the non-interactive rule + `--json` on every mutating command (Plans for `--dry-run --json`, Results otherwise); **Q** the ruled behaviour deltas (#294 lock refusals surfaced and unified, #283 global update counter, dry-run merged-artifact modelling); **R** facade and file closure (`flows.go` dissolved, `ProfileManager` gains ctx, fixture-only exports resolved, doc comments, allow-list mechanism deleted, core's no-concrete-sources test widened); **S** docs, CHANGELOG shaping, v2.0.0 readiness, phase-end live review. Same SDD loop as Phases 1–2 (fresh implementer per task, task review, fix waves, whole-branch review per unit with a twin-binary matrix, coordinator merge gate).

**Tech Stack:** Go 1.27, cobra, testify, `encoding/json/v2` (core goldens; the CLI's `--json` switches to it in Unit O), `log/slog`. No new dependencies.

**Spec:** `docs/plans/2026-08-27-v2-core-refactor-design.md` — §1 (facade shape, the boundary), §4 (core types are the JSON contract; Plan/Apply; no callbacks from Apply; stale plans), §5 "Phase 3", decisions log. Deviations are listed under **Rulings** and recorded in the decisions log by Task 1.

## Rulings (recorded in the decisions log by Task 1)

1. **Plans stay side-effect-free with respect to managed state; a cache fill is not a mutation.** Conflicts for a not-yet-cached mod are still discovered in Apply: `ApplyInstall`/`ImportArchive` download (cache), compute conflicts, and — when `opts.AcceptConflicts` is false and conflicts exist — return `*core.ConflictError` (wraps `domain.ErrFileConflict`, carries `[]Conflict`) **before any deploy or DB write**. The frontend prompts and re-runs Apply with `AcceptConflicts: true`; the second run finds the cache warm. `ConfirmConflicts` (both) and `ConfirmInstall` are deleted; `ProfileImportOptions.Install bool` replaces the latter (decidable from the plan).
2. **Non-interactive rule.** Under `--json` the CLI never reads stdin. Every prompt has a flag that decides it (`--yes`/`-y` accepts, `--force` where that is the existing meaning); `profile switch` and `profile sync` gain `-y/--yes`; `game detect` gains `--all` (select every not-yet-configured game) and `--select <list>`; without the flag, a `--json` run fails before mutating with `ErrConfirmationRequired` (exit 1, envelope). `game add` and `auth login` stay interactive-only in Phase 3 (flags for them are a follow-up issue) and reject `--json` with `ErrInteractiveOnly`.
3. **Delta — JSON shapes change once.** Every `--json` document becomes a core/domain type (or a core query type) marshalled with `encoding/json/v2` + `Deterministic(true)` + 2-space indent; the error envelope becomes `{"error": "<text>", "details": {...}}` where `details` is present only for typed errors that carry data (`ConflictError` → `{"conflicts": [...]}`, `ErrStalePlan` → none). `source list` becomes indented like everything else.
4. **Delta — deterministic ordering (#298, #299).** `ResolveReorder`'s ambiguity candidates are sorted by source ID; `PlanProfileSync` buckets are ordered by `OrderByProfile` (profile order, then installed order for additions); `ListGames`/`lmm status` order games by ID. Plain-text captures that pinned map order are re-pinned once.
5. **Delta — lock refusals surfaced and unified (#294).** `profile apply`/`profile sync` print a swallowed `UpsertMod` lock refusal as a non-verbose warning line (`Warning: …`) instead of a `-v`-only note; the four hand-worded refusals in `cmd/lmm/update.go`/`mod_edit.go` print `plan.Refusal`/`core.LockedRefRefusalError` text.
6. **Delta — global update-check counter (#283).** `UpdateCheckEvent` gains `GlobalIndex`/`GlobalTotal`; the CLI's `-v` line prints the global pair.
7. **Delta — prompt position.** `profile import`'s "Download and install mods?" prompt moves before Apply (the profile is no longer saved before the question); `install`/`import` conflict prompts appear after the download step (Ruling 1) exactly where they appeared before, but a re-run Apply may print its download line as cached — the task records the exact new lines.
8. **Delta — dry-run merged-artifact modelling.** `UninstallPlan`/`PurgePlan` gain `MergedArtifact *MergedArtifactEffect` (resync/remove, path) computed from the profile; the unconditional dry-run line becomes conditional; `ImportArchiveResult.MergedPakSynced` is set from what actually ran.
9. **Delta — `game detect` non-interactive flags** (`--all`, `--select`) add output only under those flags.
10. **Exported-method count is an output, not a target.** Every exported `*Service` method must be a flow (Plan/Apply/convenience), a query a frontend legitimately needs, or a documented test-seed API; the ≤60 number is retired. Kept by ruling: `DeployProfile`/`UninstallMod`/`PurgeProfile` (conveniences), `SaveFileChecksum` (documented test-seed API — no Plan/Apply substitute), `AvailableModVersions`/`IsSourceAuthenticated`/`ScanLocal`/`Logger` (serve needs them). Deleted: the four dead methods. Unexported via real-path seeding: `DownloadMod`, `GetInstaller`, `SetModLinkMethod`, `SetModDeployed`, `PurgeMergedPak`. `SaveInstalledMod`/`DeleteInstalledMod`/`SyncMergedPak`/`GetGameCache` lose their last cmd callers when `mod edit` and `mod files` get core flows (Unit P) and are then unexported.
11. **`ProfileManager` gains ctx** (the Phase-1 deferral never happened); the sanctioned `context.Background()` sites drop to two (db.New migrate, root.go signal root).
12. **`core` must not import any concrete source package.** The `*custom.Directory` assertion becomes a capability interface in `internal/source` (`LocalFileServer` — "may serve `file://` URLs") implemented by `custom.Directory`; core's boundary test covers every package under `internal/source/` except `internal/source` itself and `httpclient`.
13. **`flows.go` dissolves into** `mod_toggle.go`, `phases.go` (the `DeployPhase` vocabulary), `switch.go`, `profile_import.go` (not `importer.go`, which is the archive importer), `hooks.go` (`runHook`), `selection.go` (`sameFileIDSet`); `OrderByProfile` lands in `deploy.go`.
14. **v2.0.0 mechanics are the owner's call**, prepared but not executed: Unit S produces a release checklist including the **Go module path decision** (`…/linux-mod-manager/v2` suffix per semantic import versioning vs. keeping the path for a single-binary module) — the plan does not choose.
15. **`--dry-run --json` emits the Plan document**; `--json` on an applying command emits the Result document; a decline/`ErrConfirmationRequired` emits the envelope. Events are suppressed under `--json` (spec).
